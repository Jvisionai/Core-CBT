# 빈출 문제 Beta — 설계

- 작성일: 2026-07-25
- 상태: 설계 승인됨 (스펙 검토 대기)
- 범위: 정보처리산업기사 필기 "빈출 유형 열람" Beta 페이지 (읽기 전용)

## 1. 배경 · 목표

정보처리산업기사 필기는 **기출이 반복 출제**된다 — 임베딩 클러스터링으로 검증한 결과 **9회차 540문제 중 반복 콘텐츠 79%**, 과목별 반복률 75~81%. 사람이 태깅하지 않아도 임베딩이 반복 유형을 자동으로 묶는다.

목표: 이 검증된 능력을 **간단한 Beta 페이지**로 노출한다 — "이 유형이 N번 반복 출제됨"을 과목별로 보여주고, 자주 나오고(빈출) 많이 틀리는(오답률) 유형을 우선 학습 대상으로 강조.

## 2. 핵심 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 데이터 | 오프라인 미리 계산 → 정적 JSON | 런타임 임베딩·DB·인증 불필요, 배포 비용 0 |
| 임베딩 | text-embedding-3-small, `질문+보기` | 검증됨 |
| 군집 | 과목(메타데이터)별, 유사도 ≥0.86, union-find, rounds≥2 | 검증됨 (과목 착시 제거) |
| 오답률 | `problem_outcomes` 집계 (틀린수/시도수), 미리 계산 | 집계라 인증 불필요 |
| 격리 | 새 라우트 + 정적 데이터만. 기존 퀴즈·채점 코드 불변 | 리스크 최소 |

## 3. 아키텍처

```
[미리 계산 스크립트]  (커밋 시 1회 실행, 런타임 아님)
  problem2022/2023/2024 필기 로드 (과목 라벨 부착)
    → 임베딩 → 과목별 군집 → 오답률 집계(Supabase)
    → 정적 JSON 저장  →  app/frequent/_data/frequent.json

[페이지]  app/frequent/page.js (서버 컴포넌트)
  JSON import → FrequentClient.js (과목 탭 + 카드 렌더)
```

## 4. 컴포넌트

### 4.1 미리 계산 스크립트 `scripts/build-frequent-data.mjs`
- 입력: `datasets/problem2022|2023|2024/{first,second,third}/problem1.json` (9회차)
- 과목 정규화: 섹션 제목 → `정보시스템 기반기술` / `프로그래밍 언어 활용` / `데이터베이스 활용`
- 회차→세션ID 매핑 (링크·오답 조인용): 2024-1→1, 2024-2→2, 2024-3→3, 2023-1→6, 2023-2→7, 2023-3→8, 2022-1→9, 2022-2→10, 2022-3→11
- 임베딩(배치, 재시도 포함) → 과목별 union-find 군집(≥0.86) → rounds≥2 클러스터만
- **오답률 집계:** `problem_outcomes`에서 `(source_session_id, source_problem_number)`별 `시도수 / 틀린수`. 클러스터 평균 오답률 = 클러스터 내 문제들의 (총 틀린수 / 총 시도수). **시도수 < 20이면 오답률 null(표시 안 함).**
- 출력: `app/frequent/_data/frequent.json`

### 4.2 데이터 형태
```json
{
  "exam": "정보처리산업기사 필기",
  "rounds": 9,
  "generatedAt": "<빌드시 주입>",
  "subjects": [
    { "name": "정보시스템 기반기술", "total": 180, "repeatRate": 78,
      "clusters": [
        { "rounds": 6, "size": 6, "kind": "동일",
          "wrongRate": 62, "attempts": 340,
          "items": [ { "round": "2024-1", "sid": "1", "no": 3,
                       "question": "...", "options": ["...","..."] } ] } ] } ]
}
```
- 클러스터 정렬: 미리 계산 시 `빈출(rounds) × 오답률` 내림차순 (오답률 null은 뒤로)

### 4.3 페이지 `app/frequent/page.js` + `FrequentClient.js`
- 서버 컴포넌트가 JSON import → 클라이언트 컴포넌트에 전달
- 상단: 제목 + **`Beta` 뱃지** + 전체 요약(총 문제·반복률)
- **과목 탭** 3개 (클라이언트 상태 전환)
- 각 과목: 반복률 헤더 + 빈출 유형 카드 목록
  - 카드: `N회 반복 · M개 회차` + `동일`/`변형` 뱃지 + (있으면) `오답률 X%` 뱃지
  - 대표 질문 + 보기, 회차 뱃지들 → `/test/<sid>` 새 탭 링크
- Tailwind, 기존 페이지 스타일 따름 (`app/network2/page.js` 참고)

### 4.4 진입점
- `app/page.js`(메인)에 "빈출 문제 `Beta`" 링크 카드 1개 추가 → `/frequent`

## 5. 데이터 흐름
1. 개발자가 `node scripts/build-frequent-data.mjs` 실행 (문제 추가/갱신 시)
2. JSON이 repo에 커밋됨
3. 배포 시 페이지가 JSON을 import해 렌더 (런타임 계산 없음)

## 6. 오류 처리 · 제약
- **오답률 데이터 편차:** 회차별 outcome 수가 고르지 않음(세션1·10·11 많음). → 시도수 ≥20인 클러스터만 오답률 표시, 나머지는 반복 횟수만.
- JSON 없거나 파싱 실패 → 페이지는 "데이터 준비 중" 안내 (빈 배열 방어).
- 스크립트: 임베딩/Supabase 호출 재시도. Supabase 미설정 시 오답률 없이 진행(빈출만).

## 7. 테스트
- 미리 계산: 과목 3개 각각 클러스터 생성되는지, 오답률이 [0,100] 범위인지, 시도<20이면 null인지 (스크립트 assert)
- 페이지: JSON 목킹해 과목 탭 전환·카드 렌더 스냅샷 (vitest + 최소 렌더 확인)

## 8. 범위 밖 (YAGNI / Phase 2)
- 개인별 "네가 자주 틀린 유형" (인증 + 개인 오답 매칭) — 지금 클러스터가 기반
- 미니 퀴즈("이 유형만 풀기"), 오답 화면 추천 위젯 (채점 흐름 연동)
- 실기·SQLD·네트워크 등 다른 시험 (구조는 재사용 가능하나 v1은 정보처리산업기사 필기만)
- 런타임 재계산 / pgvector 연동

## 9. 성공 기준
- [ ] `/frequent` 페이지에서 과목별 빈출 유형이 반복 횟수 순으로 보인다
- [ ] 회차 뱃지 클릭 시 해당 회차 실제 시험(`/test/<sid>`)이 열린다
- [ ] 오답률은 데이터 충분(≥20시도)한 클러스터에만 표시된다
- [ ] 기존 퀴즈·채점·라우트가 전혀 바뀌지 않는다 (격리)
- [ ] JSON 재생성이 스크립트 1회 실행으로 된다
